## D-001 검수 ID 형식

- **결정:** S-04 주소 `/inspections/:id`의 `id`는 서버가 발급하는 전역 고유 ID를 쓴다. 화면에는 장비명과 장비별 순번(예: "1호기 · #0142")을 따로 표시한다.
- **이유:** 장비별 순번은 날짜·세션이 바뀌면 다시 시작될 수 있어, 주소로 쓰면 서로 다른 검수 건이 같은 주소가 될 수 있다.
- **근거:** Figma v1 S-04·S-05는 "1호기 / #0142" 형식으로 표시. 현재 코드는 `DEMO-001` 사용. 명세 V1-405는 판정자·시각 기록만 규정하고 ID 형식은 정하지 않음.
- **1단계 적용:** 목 데이터는 `DEMO-001` 형식을 전역 ID로 쓴다. 기존 주소 `/inspections/DEMO-001`은 계속 열려야 한다.
- **버린 대안:** 장비+날짜+순번 조합 ID(순번 초기화 규칙을 서버와 맞춰야 함), 서버팀 확인까지 보류.
- **남은 확인:** 실제 전역 ID 형식은 서버팀과 확정한다. 프런트는 ID를 해석하지 않고 문자열로만 다룬다.

## D-002 S-04 판정 저장 버튼

- **결정:** 판정 저장 버튼은 항상 활성 상태로 둔다. 판정(실제 오류 / AI 오검출)을 고르지 않고 누르면 판정 선택 옆에 "실제 오류 또는 AI 오검출을 선택하세요"를 표시하고 그 항목으로 포커스를 옮긴다. 저장 요청 중에만 버튼을 잠그고 "저장 중…"으로 표시한다.
- **이유:** 비활성 버튼은 왜 누를 수 없는지 알려주지 못한다. 태블릿에서는 툴팁도 뜨지 않는다.
- **근거:** `SaaS_command1.md` "Submit button stays enabled until request starts", "Errors inline next to fields; focus first error on submit". 명세 V1-405 "둘 중 하나를 선택해야 저장".
- **디자인 차이:** Figma v1 S-04는 선택 전 비활성 모양으로 그려져 있다. Figma 수정 요청 대상이다.
- **버린 대안:** Figma대로 비활성 + 안내 문구.

## D-003 저장 성공 후 동작

- **결정:** 저장에 성공하면 S-04에 들어온 화면으로 자동 복귀한다. 복귀한 화면에 "판정이 저장됐습니다 · {판정} · {오류 유형} · 미확인 N건 남음"을 표시한다(`aria-live`). 미확인 목록, 미확인 집계, 상단 배지를 다시 불러와 같은 값으로 맞춘다.
- **복귀 위치:** 실시간 검수에서 왔으면 `/live`, 이력에서 왔으면 들어올 때의 이력 URL(필터·페이지 포함), 알림에서 왔으면 알림을 연 화면, 직접 접속이면 D-004.
- **이유:** 미확인 건을 연달아 처리하는 업무 흐름에 맞다.
- **근거:** Figma v1 레이어 `P-03B · 판정 저장 후`가 S-03 상태 프레임에 있음(레이어 이름만 확인, 내용 미확인). 와이어프레임 초안 "상세 보기에서 판정이 끝나면 이력 목록으로 돌아오고". Figma E-02 저장 성공 문구.
- **실패 시:** 복귀하지 않는다. 입력을 그대로 두고 오류와 다시 저장을 표시한다. 미확인 상태를 유지한다.
- **버린 대안:** S-04에 머무름, 머물면서 "다음 미확인" 버튼 제공(순서 기준을 따로 정해야 함).

## D-004 직접 URL 접속 시 복귀 위치

- **결정:** 이전 화면 정보 없이 S-04가 열리면(링크를 새 탭으로 열거나 주소를 직접 입력한 경우) 복귀 버튼은 "실시간 검수로", 목적지는 `/live`다. 저장 후 자동 복귀도 `/live`로 간다.
- **이유:** 실시간 검수가 주 업무 화면이다.
- **근거:** 명세 V1-305 미확인 이상 선택 → S-04, V1-605 알림 확인 → S-04. 두 진입 모두 실시간 검수 업무에 속함.
- **버린 대안:** 검수 이력 `/history`(오늘·최신순).
- **참고:** 진입 정보는 브라우저 기록 상태(`location.state`)에 담는다. 같은 탭에서 새로고침하면 유지되지만, 링크를 새 탭으로 열거나 주소를 직접 입력하면 없으므로 D-004가 적용된다. 이력 조건은 이력 URL에 있으므로 이력 화면 자체는 언제든 복원된다.

## D-005 미검출 등록과 지표 (제안)

- **제안:** 정상으로 표시된 건에서도 약사가 미검출을 등록할 수 있게 설계한다. 미검출·오검출·판독 불가와 판정 소요시간을 측정한다. 이벤트와 분모는 팀과 합의한다.
- **이유:** 이상 알림만 검토하면 정상으로 분류된 건의 오류가 집계에서 빠진다. 자발적 신고만으로 전체 Recall을 추정할 수 없으므로 별도 표본 검증 기준도 필요하다.
- **명세와의 관계:** 기능명세서 V1에는 이 기능이 없다. V1-405·406은 이상 건에 대한 실제 오류 / AI 오검출 판정만 정의하고, V1-701 통계는 검수 건수·이상 건수·오검출 비율만 정의한다. 따라서 명세 추가 제안이다.
- **적용 상태:** 팀이 명세에 추가하기로 합의하기 전에는 1·2단계 범위에 넣지 않는다. 합의되면 새 항목으로 "D-005 확정"을 남긴다.
- **현재 대안:** 명세대로 AI 이상 건만 판정·집계.

## D-006 화면 문구

- **결정:** statusLabels를 기준으로 문구를 관리한다. “오류 판정”, “합격”, “AI 확정”처럼 AI 결과를 최종 판정으로 오인하게 하는 표현을 피하고 변경 시 규제 관점에서 검토한다.
- **이유:** AI 표시와 약사 확정의 의미를 분명히 한다.
- **근거:** 기존 상태 라벨과 판정 분리 기준.
- **버린 대안:** 화면마다 독립적으로 문구 작성.

## D-007 검수 이미지

- **결정:** 서버 연동 시 마스킹된 이미지만 만료 URL로 제공하고 브라우저 저장소·캐시 저장을 방지한다. 다운로드 제한과 CSV·PDF 마스킹 정책은 팀 결정 5번과 함께 확정한다.
- **이유:** 검수 이미지의 잔존과 재노출을 줄인다.
- **근거:** 기존 마스킹 실패 시 이미지 미렌더링 규칙과 내보내기 논의.
- **버린 대안:** 원본 전송 후 CSS 마스킹, 브라우저에 이미지 보관.

## D-008 로그와 기능 경계

- **결정:** 개인정보 및 이미지 URL을 로그와 오류 보고에서 제거한다. ESLint no-console 및 no-restricted-imports로 콘솔 출력과 다른 기능의 내부 모듈 직접 참조를 제한할 예정이다.
- **허용 예외:** `features/inspections`는 실시간 검수·판정·이력이 함께 쓰는 공유 도메인이다(계획 문서 §6). 다른 기능은 이 폴더의 공개 파일(`types.ts`, `constants.ts`, `api.ts`, `components/`, 저장소 훅)을 가져다 쓸 수 있다. 그 밖의 기능끼리 서로의 `pages`·`components` 내부를 직접 참조하는 것을 막는다.
- **이유:** 민감 정보 노출과 기능 간 결합을 줄인다.
- **근거:** 기존 기능별 디렉터리 구조와 이미지 보호 원칙.
- **버린 대안:** 리뷰에서만 수동 검사.

## D-009 PR 자동 검사

- **결정:** GitHub 저장소에 PR별 typecheck, lint, build를 실행하는 CI를 추가할 예정이다.
- **이유:** 제출된 변경에 같은 검증 기준을 적용한다.
- **근거:** 프로젝트의 기존 npm 검사 명령.
- **버린 대안:** 개발자 로컬 검사에만 의존.

## D-010 TanStack Query 도입 기준

- **결정:** 서버 연동 단계에서 도입 여부를 결정한다. 도입 시 기능별 key factory를 사용하고 장비별 데이터 키에 deviceId를 포함한다.
- **이유:** 장비별 캐시와 갱신 대상을 구분한다.
- **근거:** 기존 1단계 라이브러리 도입 범위.
- **버린 대안:** 목 데이터 단계에서 선제 도입.
