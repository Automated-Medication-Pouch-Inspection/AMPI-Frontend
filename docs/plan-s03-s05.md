### 3-3. 마스킹 차단 일관 규칙

1. 이미지를 보여주는 곳은 모두 공통 컴포넌트 `MaskedImage` 하나를 거친다: S-03 최신 촬영 이미지, S-04 본 이미지, 직전·직후 약포지, 알림 썸네일, 이후 S-05 썸네일.
2. 표시 조건은 `이미지 마스킹 = 정상` **그리고** `해당 장비 마스킹 ≠ 실패`다. 알 수 없음은 차단으로 처리한다(fail closed).
3. 차단 시 `<img>`를 렌더링하지 않는다. 흐림 처리나 CSS로 숨기기를 쓰지 않는다. 대신 경고 문구, 장비, 발생 시각을 표시한다.
4. 알림 팝업은 썸네일 없이 문자 알림만 띄운다. 알림 자체는 막지 않는다(V1-606 시각 알림 유지 원칙과 동일).
5. 서버 계약 요청: 마스킹 실패 이미지는 응답에 URL을 넣지 않는다. 프런트 차단만으로는 유출을 막을 수 없다.

### 4-1. 라우트 제안

### 4-2. S-04 복귀 규칙

| 진입 경로 | 전달 값 | 복귀 버튼 문구 | 복귀 위치 |
| --- | --- | --- | --- |
| S-03 미확인 목록·타임라인 | `state.from = { screen: 'live' }` | 실시간 검수로 | `/live` |
| 전역 알림 | `state.from = 알림을 연 화면의 URL` | 이전 화면으로 | 알림을 연 화면 |
| S-05 상세 보기 | `state.from = { screen: 'history', url: '/history?...&page=2' }` | 검수 이력으로 | 저장된 URL 그대로(필터·페이지 복원) |
| 직접 URL·새 탭 | 없음 | 실시간 검수로 | `/live` (D-004 확정) |

- 복귀는 `navigate(-1)`이 아니라 `<Link>`로 만든다. 새 탭으로 열기(Cmd/Ctrl+클릭)를 지원하고, 직접 URL 접속에서도 동작해야 하기 때문이다.
- S-05 조건은 URL에 있으므로 새로고침해도 유지된다. `state`가 사라져도 이력 화면 자체는 복원된다.
- 저장 성공 후에는 **진입 화면으로 자동 복귀하고 결과 안내를 띄운다**(D-003 확정). 근거는 [레이어] `P-03B · 판정 저장 후`와 [초안F] "판정이 끝나면 이력 목록으로 돌아온다"이며, P-03B 내용은 열어보지 않았다.

### 5-3. 실제 API·실시간 이벤트에 필요한 필드

- 검수 건: `id`(전역 고유), `deviceId`, `deviceName`, `sequenceNo`(#0142), `capturedAt`, `expectedCount`, `detectedCount | null`, `aiResult`, `detections[]`(검출 위치), `image { url | null, maskingStatus }`, `prevId`, `nextId`, `judgment | null { decision, errorType, memo, actionDone, actionDoneAt, judgedBy, judgedAt }`, `version`.
- 저장 요청: `decision`, `errorType?`, `memo?`, `actionDone?`, `version`, `idempotencyKey`. 응답: 저장된 판정 + 새 `version`. 오류: 401·403·404·409(충돌, 현재 판정 포함)·422(검증)·5xx 구분.
- 실시간 이벤트: `inspection.created`, `inspection.judged`(다른 약사 저장 반영), `device.status`, `session.status`, `masking.status`, `summary.updated`. 각 이벤트에 `occurredAt`과 순서 번호(재연결 후 누락 복구용).
- 이력 조회: 필터 값 목록, `page`, `pageSize`, `total`, 정렬.

## 8. 첫 구현 범위와 완료 조건

### 범위

- `/live`(S-03): 상단 집계 3개, 장비 카드 2개(정적 목 데이터), 최신 촬영 이미지, 최근 약포지 판정, 확인이 필요한 약포지 목록.
- `/inspections/:id`(S-04): 이미지 확대·이동·검출 위치 표시·초기화, 직전·직후, 판정 정보, 판정 폼, 저장, 진입 경로별 복귀.
- `/history`: 현재 목록 화면을 옮기고 URL 조건을 유지하는 수준. 전체 필터는 2단계에서 다룬다.
- 상단바 미확인 배지, 브라우저 끊김 배너, `MaskedImage`.
- 목 저장소에 지연과 실패 주입(개발 전용 쿼리 또는 개발 패널).

### 완료 조건

1. `/inspections/DEMO-001`이 판정 화면으로 열린다. `/inspections/NOPE-999`는 "검수 건을 찾을 수 없습니다"와 복귀 링크를 보여준다. 정의되지 않은 경로는 NotFound다.
2. S-03 미확인 항목 → S-04 → 판정 저장 → S-03 복귀. 해당 건이 목록에서 빠지고, 미확인 집계와 상단 배지가 같은 값으로 1 줄어든다.
3. 저장하지 않고 돌아가거나 알림만 닫으면 미확인이 유지된다. 판독 불가 건도 판정 전까지 목록에 남는다.
4. 저장 실패를 주입하면 입력값(판정·오류 유형·메모·조치 완료)이 그대로 남는다. 원인별 오류 문구와 다시 저장이 표시되고, 미확인이 유지되며, "저장됨"이 표시되지 않는다.
5. 저장 중 버튼을 여러 번 눌러도 요청은 1회만 나간다.
6. 오류 유형과 조치 완료는 실제 오류를 선택했을 때만 활성화된다. AI 오검출로 저장하면 두 값이 전송되지 않는다.
7. 이력 필터 복원: `/history`에서 조건·페이지를 바꾼 뒤 상세로 갔다가 "검수 이력으로"를 누르면 같은 URL과 결과로 돌아온다. 새로고침해도 조건이 유지된다.
8. 네트워크·장비 단절 구분: 브라우저를 오프라인으로 바꾸면 브라우저 연결 배너가 뜨고, 저장 시 네트워크 오류로 안내하며 입력이 유지된다. 목 장비 오프라인은 장비 카드에만 표시되고 브라우저 배너와 섞이지 않는다.
9. 마스킹 차단: 마스킹 실패 목 데이터에서 S-03 최신 이미지, S-04 본 이미지, 직전·직후 위치에 `<img>` 요소가 DOM에 없고 경고 문구가 보인다.
10. 키보드: Tab으로 미확인 항목에 가서 Enter로 S-04를 연다. 방향키로 판정을 고르고 Tab·Enter로 저장한다. 포커스가 항상 보이고, 저장 결과는 `aria-live`로 읽힌다. 검증 오류가 나면 첫 오류 항목으로 포커스가 간다. 이미지 확대·이동은 버튼과 키보드로도 된다.
11. 태블릿: 1024×768 가로와 768×1024 세로에서 가로 스크롤이 없다. 터치 대상은 44px 이상이다. 핀치 없이 버튼으로 확대할 수 있다. hover 없이 모든 동작을 쓸 수 있다.
12. `npm run typecheck`, `npm run lint`, `npm run build`가 통과한다.

### 검증 계획

- 브라우저 시나리오(내장 브라우저, `npm run dev`): 위 1~11을 순서대로 수행하고, 각 단계의 화면·DOM(`<img>` 유무, `aria-live`)·URL을 기록한다. 오프라인은 브라우저 네트워크 차단 또는 목 플래그로 재현한다. 태블릿은 뷰포트 1024×768, 768×1024로 확인한다.
- 명령: `npm run typecheck`, `npm run lint`, `npm run build`.
- 단위 검증 후보(테스트 도구 도입은 별도 결정): `judgmentRules.ts`의 활성·검증 규칙, `historyQuery.ts`의 URL 변환, 목 저장소의 저장 후 미확인 수 계산.
- 보고 시 실제 서버·장비·AI 연동을 검증하지 않았다는 점을 시연 결과와 구분해 적는다.
