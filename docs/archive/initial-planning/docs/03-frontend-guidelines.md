# Medilux 프런트엔드 지침

외부 UI 지침을 참고해 작성한 프로젝트용 적용안이다. 의료 규정이나 임상 검증 기준을 대신하지 않으며, 실제 업무 요구사항은 별도로 확정한다.

## 화면

- 한국어 업무 용어를 일관되게 사용한다. 같은 상태에 여러 이름을 붙이지 않는다.
- 장식보다 약품명·수량·이미지·검토 상태의 가독성을 우선한다.
- AI 결과와 작업자 결정, 저장 상태는 서로 다른 항목으로 표시한다.
- 상태는 색상과 함께 텍스트·아이콘으로 표시한다.
- 원본 이미지의 확대·축소와 초기화 기능을 제공한다. 검수에 필요한 원본 영역을 임의로 잘라 숨기지 않는다.
- 좁은 화면에서도 필수 정보에 접근할 수 있게 하고, 상세 비교는 넓은 작업 화면을 우선 설계한다.
- 필터·검색·페이지는 URL로 복원할 수 있게 한다. 날짜는 시간대와 표시 기준을 명확히 한다.
- 데이터 갱신 중 작업자의 입력이나 선택을 임의로 초기화하지 않는다.

## 입력·접근성

- 동작은 button, 이동은 link, 입력에는 label을 사용한다.
- 아이콘만 있는 버튼에도 이해할 수 있는 이름을 제공한다.
- 키보드로 주요 작업을 수행할 수 있고 현재 포커스가 보여야 한다.
- 오류는 문제가 있는 입력 근처에 설명하고 복구 방법을 안내한다.
- 로딩·빈 목록·검색 결과 없음·통신 실패·연결 끊김을 구분한다.
- 애니메이션은 절제하고 동작 줄이기 설정을 존중한다.
- 수량·점수 열은 비교하기 쉽게 정렬하며 소수점·단위를 일관되게 표시한다.

## React·TypeScript

- TypeScript 엄격 모드를 기본으로 하고 API 응답을 런타임에도 검증한다.
- API 요청을 화면 곳곳에 복제하지 않고 기능별 api 파일로 모은다.
- 데이터에서 계산 가능한 값은 불필요한 별도 상태로 중복 저장하지 않는다.
- 독립적인 요청을 불필요하게 순차 실행하지 않는다.
- 큰 이미지와 목록의 성능은 실제 데이터량을 기준으로 확인한다.
- 최적화는 측정하거나 확인한 병목에 적용하고 useMemo 등을 일괄 추가하지 않는다.
- Next.js 전용 서버 규칙은 Vite 프로젝트에 그대로 적용하지 않는다.

## 검수 결과 저장

- AI 분석 완료를 작업자 검토 완료로 간주하지 않는다.
- 저장 중 중복 제출을 막고 서버 응답을 받은 후 저장 완료로 표시한다.
- 충돌·권한 오류·연결 실패를 구분하고 실패한 저장의 재시도 방법을 제공한다.
- 서버 연동 시 저장 요청에 버전과 중복 방지 식별자를 포함하는 방법을 검토한다.
- 검토 결과 변경에는 담당자·시각·이전 값·변경 사유를 서버에서 기록한다.

## 검증

핵심 검증 대상은 잘못된 상태 전환, 저장 실패, 중복 저장, 동시 수정, 주요 키보드 흐름이다. 외형만 바뀐 변경에 구현을 그대로 반복하는 테스트를 늘리지 않는다. 실제 AI·장비·인증 연동을 검증하지 않았다면 시연 결과와 구분해 설명한다.
