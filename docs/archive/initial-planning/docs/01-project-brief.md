# 프로젝트 범위 제안

## 확인된 목표

- 프로젝트: AI 기반 ATDPS 후장착 약품 자동검수 시스템
- 우선 웹으로 개발한다.
- 공개 프런트엔드 지침과 유사 오픈소스 앱을 참고한다.

## 이번 구성에서 제안하는 방향

검수 담당자가 브라우저에서 검수 대기 목록을 열고, 약품 이미지·기대 정보·AI 분석 결과를 비교한 뒤 작업 결과를 기록하는 업무용 웹앱을 가정한다. 사용자의 실제 직무, 입력 데이터와 장비 사양은 아직 확인하지 않았다.

## 첫 시제품의 화면

| 화면 | 주요 내용 | 우선순위 |
| --- | --- | --- |
| 대시보드 | 대기·처리 중·확인 필요·완료 건수, 최근 작업 | 2 |
| 검수 목록 | 상태·시간·장비 필터, 검색, 정렬, 상세 이동 | 1 |
| 검수 상세 | 원본 이미지, 기대 정보, AI 결과, 작업자 검토 | 1 |
| 약품 목록 | 약품 코드·이름·규격 검색과 상세 | 2 |
| 장비 목록 | 장비 ID, 연결 상태, 최근 수신 시각 | 3 |
| 변경 이력 | 누가 언제 어떤 결과를 변경했는지 조회 | 2 |
| 설정 | 표시 옵션, 사용자·역할 관리의 화면 자리 | 3 |

첫 개발은 검수 목록 → 검수 상세 → 결과 기록의 흐름으로 제한한다. 장비 연결 상태와 AI 결과는 처음에는 가상 데이터로 표시하고 화면에 시연 모드임을 명시한다.

## 초기 범위 밖

- 실제 약품 식별 모델의 학습·정확도 검증
- ATDPS·카메라 직접 제어 및 현장 설치
- 실제 처방 시스템 연동과 운영 데이터 이전
- 과금·구독·기관 가입 자동화

`SaaS`라는 이름만으로 다기관 과금 시스템 구현까지 확정하지 않는다. 기관별 데이터 분리와 서버 권한 검사는 실제 서비스 구현 전에 정의한다.

## 성공 기준

- 가상 검수 건을 목록에서 찾아 상세 화면까지 이동할 수 있다.
- 기대 정보, AI 결과, 작업자 결정을 혼동 없이 읽을 수 있다.
- 대기·실패·재시도·연결 끊김 상태를 구별할 수 있다.
- 저장 실패를 완료로 표시하지 않는다.
- 화면 검토 후 실제 연동 범위를 결정할 수 있다.

## 구현 전 확인할 사항

검수 단위(파우치·트레이·처방 등), 기대 약품 정보의 출처, 담당자 역할, 판정 종류, AI 점수 의미, 장비 통신 방법, 이미지 보관 위치와 보존 기간은 미정이다. 이 문서의 제안으로 확정된 것으로 처리하지 않는다.
