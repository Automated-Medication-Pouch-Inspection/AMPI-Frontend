# 프런트엔드 개발 기준

- 화면은 `features/<기능>/pages`, 해당 기능의 표·폼은 같은 기능의 `components`에 둡니다.
- 여러 기능에서 공통으로 쓰는 UI만 `src/components`에 둡니다.
- 서버 요청은 기능별 `api.ts`, 공통 전송 처리는 `lib/api/client.ts`에 둡니다.
- `contexts`에는 Provider를 둡니다. `store`는 전역 상태가 필요해질 때 추가합니다.
- Ant Design 기본 표·입력·상태 표시를 사용하고 CSS 토큰으로 색상·간격을 일관되게 관리합니다.
- 장식보다 목록 가독성·명확한 상태·키보드 접근을 우선합니다.
- 가상 데이터와 실제 API를 구별하고 저장하지 않은 결과를 저장 완료로 표시하지 않습니다.
- 새 기능을 추가할 때 타입 검사·린트를 실행하고, 핵심 행동 변경에는 해당 행동을 검증합니다.
- 기존 기획 문서는 보관 자료입니다. 서버·AI·장비 구현은 이 프로젝트의 현재 범위에 포함하지 않습니다.

## 추가 개발 기준

- 정상 표시 건의 미검출 등록과 지표 측정은 명세에 없는 제안(D-005)입니다. 팀이 명세에 추가하기 전에는 구현하지 않습니다.
- 상태 문구는 `statusLabels`를 기준으로 관리하며, AI 결과를 최종 판정처럼 표현하지 않습니다.
- 마스킹에 실패하면 이미지 요소를 렌더링하지 않습니다. 이미지 만료, 캐시 방지 및 다운로드 정책은 서버 연동과 함께 다룹니다.
- 로그와 오류 보고에 개인정보나 이미지 URL을 남기지 않습니다. ESLint 제약과 PR 자동 검사는 후속 작업으로 추가합니다. 기능 간 참조 제한에서 공유 도메인 `features/inspections`는 예외입니다.
- TanStack Query 도입 여부와 쿼리 키 규칙은 서버 연동 단계에서 적용 여부를 결정합니다.

상세 근거와 적용 상태는 [결정 기록](decisions.md)의 D-005~D-010을 참고합니다.
